Setting Up Node.js and the JavaScript Engine

What Node.js is and why it matters

Node.js is a platform for interpreting JavaScript code and running applications. JavaScript has been around for a couple of decades; with every improvement, it has shifted further from being a client-side scripting language to a full-fledged server-side programming language for managing data.

Because Node.js is built with Google Chrome's JavaScript engine (V8), it's considered powerful and able to support JavaScript as a server-side language. Developers can now commit to mastering JavaScript to build a complete web application instead of having to master multiple languages.

Node.js operates on an event loop using a single thread. A thread is the bundle of computing power and resources needed for the execution of a programmed task. Node.js handles only one task at a time and uses more threads only for tasks that can't be handled by the main thread. This makes Node.js fast and efficient for most web applications.

Web development can largely be broken into two categories: client-side (front-end) code that results in something the user sees in the browser, and server-side (back-end) code used for application logic. Node.js blurs the line by allowing JavaScript on both sides.

Node.js is popular for real-time applications that persistently listen for data being sent back and forth. The event loop can be thought of as an office manager: it handles incoming messages and tasks, always working on one task at a time and offloading larger tasks when necessary.

// Example of asynchronous flow
callMe();
document.body.style.background = "green";
console.log("my comment");

function callMe() {
  setTimeout(function() {
    console.log("function called");
  }, 1000);
}

Key Ideas

  • Node.js is an asynchronous, event-driven runtime built on Chrome's V8 engine.
  • JavaScript can be used on both client and server, enabling full-stack development with one language.
  • The event loop handles tasks on a single thread, offloading heavier work when needed.
  • Client-side code handles browser interaction; server-side code handles application logic and data.

Creating a Node.js Module

Organize code into reusable modules with exports and require

A Node.js application is made up of many JavaScript files. To stay organized, these files need to access one another's contents when necessary. Each JavaScript file or folder containing a code library is called a module.

To share code from a module, you add properties to the exports object. For example, exports.messages = ["You are great!", ...] makes the messages array available to other files.

To import a module, use the require function. require("./messages") looks for a file called messages.js in the same directory and returns its exports object.

With your installation of Node.js, you also got npm, a package manager for Node.js. npm is responsible for managing external packages — modules that others built and made available online. You use npm to install, remove, and modify these packages.

To initialize a new Node.js application, run npm init in your project directory. This creates a package.json file that defines the properties of your project, including its dependencies.

You can install packages with npm install <package> --save. The --save flag adds the package to your package.json dependencies. For example, the cities package converts ZIP codes to location coordinates.

// messages.js
exports.messages = ["You are great!", "You can accomplish anything!", "Success is in your future!"];

// printMessages.js
const messageModule = require("./messages");
messageModule.messages.forEach(m => console.log(m));

// main.js — using the cities package
const cities = require("cities");
var myCity = cities.zip_lookup("10016");
console.log(myCity);

Key Ideas

  • Modules are individual JavaScript files that can share code via the exports object.
  • require() imports modules into the current file.
  • package.json defines a project's metadata and dependencies.
  • npm init initializes a new project; npm install adds packages.
  • Modules, packages, and dependencies are the building blocks of Node.js applications.

Building a Simple Web Server in Node.js

Use the http module to create a server that responds to requests

Web servers are the foundation of most Node.js web applications. They allow you to load images and HTML pages to users. A web server is software designed to respond to requests over the internet by loading or processing data.

Web servers follow the Hypertext Transfer Protocol (HTTP). The two most widely used HTTP methods are GET (requests information) and POST (sends information to the server). Most web applications have adopted HTTPS, which encrypts data transmission.

Node.js comes with a built-in http module that you can use to build a web server. You create a server with http.createServer(), passing a callback function that runs whenever a request is received. The callback receives req (request) and res (response) objects.

To send a response, you use res.writeHead() to set the HTTP status code and headers, then res.write() to write the body, and res.end() to close the connection. You must call end(), or the client will hang.

Finally, call app.listen(port) to start the server. Port 3000 is commonly used for development. You can stop the server by pressing Ctrl-C in the terminal.

const port = 3000,
  http = require("http"),
  httpStatus = require("http-status-codes"),
  app = http.createServer((req, res) => {
    console.log("Received an incoming request!");
    res.writeHead(httpStatus.OK, {
      "Content-Type": "text/html"
    });
    let responseMessage = "
Hello, Universe!
";
    res.write(responseMessage);
    res.end();
    console.log(`Sent a response: ${responseMessage}`);
  });

app.listen(port);
console.log(`The server has started and is listening on port number: ${port}`);

Key Ideas

  • Node.js's http module lets you create a web server with minimal code.
  • HTTP requests and responses follow a standardized protocol with methods like GET and POST.
  • The createServer callback receives request and response objects.
  • res.writeHead(), res.write(), and res.end() compose a response.
  • Callbacks are central to Node.js's asynchronous, non-blocking behavior.

Handling Incoming Data

Collect request data and build your first routes

Every time a user visits a URL that leads to your application, a request is made. You can gather and process information from these requests by examining the request object.

Each request object has a url property and a method property. You can log these to see which URL and HTTP method the client used. For POST requests, the data lives in the request body and arrives in chunks. You listen for data events and collect the chunks into an array, then convert the array to a string when the end event fires.

Routes let you determine how your application should respond to a request made to a specific URL. A route maps a URL path to a response. You can create a simple route map object and check req.url against it.

You can also test POST requests with the curl command. curl --data "username=Jon&password=secret" http://localhost:3000 sends a POST request with form data.

const routeResponseMap = {
  "/info": "
Info Page
",
  "/contact": "

",

",
  "/hello": "

const app = http.createServer((req, res) => {
  res.writeHead(200, { "Content-Type": "text/html" });

Key Ideas

  • Request data can be accessed via req.url, req.method, and the request body.
  • POST data arrives in chunks; you must collect them and concatenate them into a string.
  • Routes map URL paths to specific responses, enabling different content for different pages.
  • curl is a command-line tool for testing HTTP requests.

Writing Better Routes and Serving External Files

Serve HTML files, images, CSS, and JavaScript with the fs module

Instead of embedding HTML in your server code, you can store HTML files in a views folder and serve them with the fs (file system) module. fs.readFile() reads a file's contents and passes them to a callback.

You can create a route map that pairs URLs with file paths. When a request comes in, you look up the URL, read the corresponding file, and send its contents as the response.

To serve assets like images, CSS, and client-side JavaScript, create a public folder with subfolders for images, css, and js. Then create routes that check the file extension and set the appropriate Content-Type header.

As your application grows, it's best to move your routes into a separate module (router.js). This module can export a handle function that processes requests, and get and post functions that register new routes.

The handle function checks routes[req.method][req.url] and calls the matching callback. If no route matches, it responds with a 404 error. The get and post functions add entries to the routes object.

// router.js
const httpStatus = require("http-status-codes"),
  htmlContentType = { "Content-Type": "text/html" },
  routes = { "GET": {}, "POST": {} };

exports.handle = (req, res) => {
  try {
    if (routes[req.method][req.url]) {
      routes[req.method][req.url](req, res);
    } else {
      res.writeHead(httpStatus.NOT_FOUND, htmlContentType);
      res.end("
No such file exists
");
    }
  } catch (ex) {
    console.log("error: " + ex);
  }
};

exports.get = (url, action) => {
  routes["GET"][url] = action;
};

exports.post = (url, action) => {
  routes["POST"][url] = action;
};

Key Ideas

  • The fs module reads files from the filesystem and serves them to clients.
  • Organize views (HTML) and public assets (CSS, JS, images) into separate folders.
  • Routes can be moved into a separate module for cleaner code organization.
  • Content-Type headers tell the browser what kind of file is being sent.
  • A catch-all route handles 404 errors.

Setting Up an App with Express.js

Install Express and create your first framework-based server

A web framework is a module that offers structure to your application. Express.js is the most popular framework for Node.js. It provides methods and modules for handling requests, serving static and dynamic content, connecting databases, and keeping track of user activity.

Express.js came out in 2010 and has a large community. Other frameworks include Koa.js, Hapi.js, Sails.js, and Total.js, but Express.js is the most widely used and supported.

To use Express.js, initialize a project with npm init and install it with npm install express --save. Then require it and create an app: const express = require("express"), app = express();. You can define routes with app.get(), app.post(), etc.

Express.js acts as middleware — it sits between HTTP requests and your application code. It provides request data through req.params, req.body, req.url, and req.query, making it easier to extract information from incoming requests.

const port = 3000,
  express = require("express"),
  app = express();

app.get("/", (req, res) => {
  res.send("Hello, Universe!");
});

app.listen(port, () => {
  console.log(`The Express.js server has started and is listening on port number: ${port}`);
});

Key Ideas

  • Express.js is a web framework that provides structure and built-in tools for Node.js applications.
  • It simplifies routing, request parsing, and static file serving.
  • Middleware functions sit between requests and responses.
  • req.params, req.body, req.query, and req.url make request data accessible.

Routing in Express.js

Build routes with parameters, middleware, and MVC controllers

Express.js routes are defined with the app object: app.get(), app.post(), app.put(), app.delete(). The route path and callback function are the two key arguments.

Route parameters are placeholders in the path, marked with a colon. For example, app.get("/items/:vegetable", ...) captures whatever value appears after /items/ and makes it available as req.params.vegetable.

Middleware functions are functions that run before your route handler. app.use() registers middleware that runs on every request or on requests matching a specific path. Middleware receives req, res, and next; calling next() continues to the next function.

The MVC (model-view-controller) pattern organizes your application into three parts: models (data), views (display), and controllers (logic). In Express.js, route callbacks act as controllers. You can move them into separate controller modules for cleaner code.

express-generator is a package that scaffolds an Express.js application with a predefined structure. Install it globally with npm install express-generator -g and run express project_name to create a new project.

// Route with parameters
app.get("/items/:vegetable", (req, res) => {
  let veg = req.params.vegetable;
  res.send(`This is the page for ${veg}`);
});

// Middleware for logging
app.use((req, res, next) => {
  console.log(`request made to: ${req.url}`);
  next();
});

Key Ideas

  • Express.js routes use HTTP methods and paths with optional parameters.
  • Middleware functions run before route handlers and can modify requests.
  • The MVC pattern separates data (models), display (views), and logic (controllers).
  • Route callbacks can be moved to separate controller files for organization.
  • express-generator provides scaffolding for new projects.

Use EJS to render dynamic views with data from controllers

Templating engines let you embed dynamic data in your views. Express.js works with many engines; this book uses EJS (Embedded JavaScript). EJS files have the .ejs extension and allow JavaScript logic inside HTML.

To use EJS, install it with npm install ejs --save and set app.set("view engine", "ejs"). Then use res.render("viewName", { data }) to render a view with data.

The set method is used to configure application settings. For example, app.set("port", process.env.PORT || 3000) sets the port to an environment variable or a default.

Controllers pass data to views by including an object in the res.render call. In the view, you use <%= variable %> to output a value.

Layouts and partials reduce repetition. Install express-ejs-layouts and add app.use(layouts). A layout file wraps every view, with <%- body %> marking where the view content goes. Partials are reusable snippets included with <%- include partials/navigation %>.

Configurations and Error Handling

Set up start scripts and handle errors gracefully

You can add an npm start script to package.json so you don't need to remember the name of your main file. Add "start": "node main.js" to the scripts object. Then run npm start to launch the app.

Express.js handles errors through middleware. A normal middleware function has three arguments (req, res, next); an error-handling middleware function has four (error, req, res, next). You can create an error controller with functions that log errors and send custom error pages.

A 404 handler catches requests for routes that don't exist. A 500 handler catches internal server errors. These middleware functions must be placed after all other routes.

Express.js can serve static files automatically. Add app.use(express.static("public")) to serve everything in the public folder. This makes it easy to serve images, CSS, JavaScript, and custom error pages.

// package.json
"scripts": {
  "test": "echo \"Error: no test specified\" && exit 1",
  "start": "node main.js"
}

// errorController.js
const httpStatus = require("http-status-codes");

exports.respondNoResourceFound = (req, res) => {
  let errorCode = httpStatus.NOT_FOUND;
  res.status(errorCode);
  res.sendFile(`./public/${errorCode}.html`, { root: "/" });
};

exports.respondInternalError = (error, req, res, next) => {
  let errorCode = httpStatus.INTERNAL_SERVER_ERROR;
  res.status(errorCode);
  res.send(`${errorCode} | Sorry, our application is experiencing a problem!`);
};

// main.js
app.use(express.static("public"));
app.use(errorController.respondNoResourceFound);
app.use(errorController.respondInternalError);

Key Ideas

  • The npm start script lets you run the app without specifying the main file.
  • Error-handling middleware has four arguments and must be placed after all routes.
  • 404 handlers catch missing routes; 500 handlers catch internal errors.
  • express.static() serves static files from a folder.

Adding API Security

Protect your API with tokens and JSON Web Tokens

APIs can be accessed by any client that can make HTTP requests, so you need to secure them. The simplest approach is a single shared token: middleware checks the apiToken query parameter against a value stored in process.env.TOKEN or a default. This is a thin layer of security — the more users who know the token, the more likely it leaks.

A better approach is a per-user token. Add an apiToken field to the User schema and generate a random token with the rand-token package in a pre("save") hook: user.apiToken = randToken.generate(16). The middleware then looks up a user whose apiToken matches the query parameter.

JSON Web Tokens (JWT) offer the strongest option for API authentication. A JWT has three parts: header, payload (usually the user ID), and signature. The server signs the token on login, and the client sends it back in the request headers.

Use the jsonwebtoken package. The apiAuthenticate action uses passport.authenticate with a callback that signs a token containing the user's ID and an expiration date. The verifyJWT middleware then reads the token from the request headers, verifies it with the secret passphrase, decodes the payload, and confirms the user still exists.

// user.js — per-user token hook
const randToken = require("rand-token");
userSchema.pre("save", function(next) {
  let user = this;
  if (!user.apiToken) user.apiToken = randToken.generate(16);
  next();
});

// usersController.js — issue a JWT
apiAuthenticate: (req, res, next) => {
  passport.authenticate("local", (errors, user) => {
    if (user) {
      let signedToken = jsonWebToken.sign(
        { data: user._id, exp: new Date().setDate(new Date().getDate() + 1) },
        "secret_encoding_passphrase"
      );
      res.json({ success: true, token: signedToken });
    } else {
      res.json({ success: false, message: "Could not authenticate user." });
    }
  })(req, res, next);
}

// usersController.js — verify a JWT
verifyJWT: (req, res, next) => {
  let token = req.headers.token;
  if (token) {
    jsonWebToken.verify(token, "secret_encoding_passphrase", (errors, payload) => {
      if (payload) {
        User.findById(payload.data).then(user => {
          if (user) next();
          else res.status(httpStatus.FORBIDDEN).json({ error: true, message: "No User account found." });
        });
      } else {
        res.status(httpStatus.UNAUTHORIZED).json({ error: true, message: "Cannot verify API token." });
      }
    });
  } else {
    res.status(httpStatus.UNAUTHORIZED).json({ error: true, message: "Provide Token" });
  }
}

Key Ideas

  • API security protects data from unauthorized clients.
  • A single shared token is simple but limited.
  • Per-user tokens generated with rand-token offer individualized security.
  • JWTs encode a user's ID and are verified via a secret signature on each request.
  • Store secrets in environment variables, not in code.

    JavaScript Syntax Introduced in ES6

    Modern JavaScript syntax used throughout this book

    ES6 (ECMAScript 2015) introduced new syntax that is now standard in Node.js applications. This appendix covers the keywords and patterns used throughout the book.

    The let keyword defines variables scoped to the block in which they're declared. Unlike var (function-scoped), let prevents accidental variable leakage between blocks. Use let for variables that change.

    The const keyword declares variables that cannot be reassigned. Use const for values you don't intend to change — including module imports like const http = require("http").

    String interpolation with backticks (`) and ${} lets you embed expressions in strings. For example: `It is ${x} degrees outside!`. This is cleaner than string concatenation.

    Arrow functions (=>) provide a shorter syntax for functions and preserve the outer this context. For example: let printName = name => console.log(`My name is ${name}`);. Arrow functions are widely used with callbacks, promises, and Mongoose queries.

    The REPL (Read-Evaluate-Print Loop) is a Node.js environment for running JavaScript interactively. Type node in a terminal to enter, and use the repl module to embed a custom REPL in your application code.

    // let — block scoped
function sample() {
  var num = 60;
  if (num > 50) {
    let num = 0;
  }
  console.log(num); // 60
}

// const — cannot be reassigned
const http = require("http");
// http = require("express"); // throws Duplicate Declaration Error

// String interpolation
var x = 45;
console.log(`It is ${x} degrees outside!`);

// Arrow functions
let printName = name => console.log(`My name is ${name}`);

// Custom REPL
const repl = require("repl"),
  replServer = repl.start({ prompt: "> " });
replServer.context.name = "Jon Wexler";
replServer.context.multiply = require("./multiply").multiply;

    Key Ideas

    • let and const provide safer scoping than var.
    • String interpolation with backticks makes strings cleaner and easier to edit.
    • Arrow functions are concise and preserve the outer this context.
    • The REPL is a quick way to test code, and the repl module can embed REPL in your app.

    Logging and Using Node.js Global Objects

    Debug effectively with console and understand the global environment

    The console module is a global object that provides logging functions. console.log prints standard output; console.error logs errors; console.info and console.warn are aliases. In a browser, these appear with different styles.

    console.time and console.timeEnd measure the time between two labeled points. Wrap an operation and see how long it took: console.time("operation"); ...; console.timeEnd("operation").

    Node.js provides several global objects. __dirname returns the absolute path to the current directory, and __filename returns the absolute path to the current file. process references the running process and gives access to environment variables (process.env), command-line arguments (process.argv), and more.

    Other key global objects come from module loading. module references the current module, exports is the shared key-value object for a module's public API, and require imports code from other modules.

    Mastering these objects makes debugging and structuring applications easier. console messages are your first tool when something breaks; understanding process.env is essential for production configuration.

    // Logging functions
console.log("Standard output log message");
console.error("Error output log message");
console.info("Standard output log message");
console.warn("Error output log message");

// Timing
console.time("function xyz");
(function xyz() {
  setTimeout(function() {
    console.log("prints first");
    console.timeEnd("function xyz");
  }, 1000);
})();

// Global objects
console.log(__dirname);  // /Users/Jon/Desktop
console.log(__filename); // /Users/Jon/Desktop/filename_example.js
console.log(process.env.NODE_ENV);

// Module API
exports.accessibleFunction = () => {
  console.log("hello!");
};
const http = require("http");

    Key Ideas

    • console provides logging functions for debugging.
    • console.time and console.timeEnd measure operation durations.
    • __dirname and __filename give absolute paths for the current file.
    • process.env accesses environment variables; process represents the running process.
    • module, exports, and require are the basis of Node.js modules.

    Glossary

    Key terms from across the book

    API (application programming interface)
    An interface through which clients can interact with your application's data — often JSON endpoints that external apps or AJAX requests can consume.
    Arrow function
    ES6 shorthand for functions that preserves the outer this context; used throughout the book for callbacks and promise chains.
    bcrypt
    A password hashing library that combines a user's password with a salt and hashes it so the plain-text password is never stored.
    Callback
    A function passed to another function to be invoked when an operation completes; central to Node.js's asynchronous model.
    Chai / Mocha
    Chai is an assertion library; Mocha is a testing framework. Together they let you write and run tests.
    connect-flash
    Express.js middleware that stores temporary messages in a session and displays them on the next page load.
    Cookie
    A small file stored on the client by the browser and sent back to the server with each request, used here for session data.
    CRUD
    Create, Read, Update, Delete — the four fundamental operations on data in an application.
    EJS (Embedded JavaScript)
    A templating engine that lets you embed JavaScript inside HTML views, using <% %> and <%= %> tags.
    Event loop
    Node.js's single-threaded mechanism for handling asynchronous tasks, queuing work and offloading heavy operations to the host system.
    Express.js
    A web framework for Node.js that provides routing, middleware, view rendering, and static file serving out of the box.
    Flash message
    A short notification (success or error) stored in a session and shown once on the next page, used with connect-flash.
    fs (file system) module
    A Node.js core module for reading and writing files, used to serve HTML files and static assets.
    HTTP method
    The type of request: GET (retrieve), POST (submit), PUT (update), DELETE (remove).
    JWT (JSON Web Token)
    A signed or encrypted token containing user data, used to authenticate API requests without a browser session.
    Middleware
    A function that runs between the incoming request and the route handler; can modify requests and responses or pass control with next().
    Mongoose
    An object-document mapper (ODM) that provides schemas, models, and queries for MongoDB.
    MVC (model-view-controller)
    An architectural pattern that separates data (models), display (views), and logic (controllers).
    npm (Node Package Manager)
    The package manager for Node.js; used to install external packages, manage dependencies, and run scripts.
    ObjectId
    A unique MongoDB identifier assigned to every document, used for lookups and model associations.
    Passport.js
    Authentication middleware for Node.js; handles strategies like local login and integrates with express-session.
    Polling / long polling
    Techniques for repeatedly requesting fresh data from the server. Long polling keeps requests open longer to reduce frequency.
    Promise
    A JavaScript object that represents the eventual result of an asynchronous operation, with .then() and .catch() methods.
    REPL (Read-Evaluate-Print Loop)
    An interactive Node.js shell for running JavaScript one line at a time.
    Route
    A mapping between an HTTP method + URL path and the code that handles requests to that path.
    Schema
    A Mongoose blueprint describing the fields, types, and validations of documents in a collection.
    Session
    Server-side storage of data about a user's interaction with the application across multiple requests.
    Socket.io
    A library that adds web-socket capabilities to a Node.js server for real-time communication.
    Static file
    A file (image, CSS, client-side JavaScript) served to the browser without server-side processing.
    TDD (test-driven development)
    Writing tests before implementation; tests define the behavior the code must satisfy.
    Virtual attribute
    A computed property on a Mongoose model that is not stored in the database (e.g., fullName).
    Web server
    Software that responds to requests over the internet by loading, processing, or generating data.
    Web socket
    A protocol that provides a persistent, bidirectional connection between client and server for real-time data.
